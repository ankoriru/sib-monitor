=== ПОЛНОЕ ОПИСАНИЕ ФУНКЦИОНАЛА ===

Версия: 2026.10.30-timeouts.1

1. АРХИТЕКТУРА
   - FastAPI + PostgreSQL (партиционированная) + Playwright + aiohttp + Chart.js + BCrypt
   - 4 фоновых потока: check_worker (60с), ssl_whois_worker (4ч), daily_report_worker (09:00), rotation_worker (03:00)
   - 15 API endpoints

2. БАЗА ДАННЫХ
   - logs: партиционированная по timestamp (авто-партиции на 3 мес вперед)
   - checks_agg: 5-мин агрегаты (uptime, avg/min/max response)
   - incidents: история падений с resolved статусом
   - monitored_sites: управляемый список с группами (key/stdo/external/self) + порог алерта
   - health: heartbeat воркера
   - latest_status: обычная таблица с последними результатами проверок.
     check_error — причина ошибки последней HTTP-проверки; очищается при восстановлении.
   - monitored_sites.http_timeout_seconds: индивидуальный HTTP-таймаут, целое число
     от 1 до 60 секунд, по умолчанию 8. Проверка диапазона есть в API и в БД.

3. DASHBOARD (/) — 4 вкладки
   - Список: группировка (Ключевые / СТДО / Внешние), sibur.ru всегда первый, KPI под каждой группой
     - Под статусом и в «Обратите внимание» показана причина: DNS, TLS, таймаут,
       отказ/сброс соединения, HTTP-код или Content Match.
     - Время проверки измеряется монотонными часами после выхода из очереди,
       включая чтение содержимого и ошибки; условные 25 секунд больше не подставляются.
   - Аналитика: Chart.js графики (14 дней), lazy load, кнопка "Показать все внешние"
   - Инциденты: последние 100 за 30д, первые 20 видны + кнопка, колонка Статус (Active/Resolved)
   - Календарь: SSL + домен, сортировка по дням, прокрутка если широкая таблица

4. KPI БЛОК
   - Доступно: online / total (danger если offline)
   - Uptime: 24ч / 30д (взвешенное среднее из checks_agg)
   - Ответ: 24ч / 30д
   - Инциденты: active + offline (danger если active>0, подпись "(N active)")
   - SSL <=20д: danger если есть
   - ⚠️ Обратите внимание: Offline + SSL <=20 + Задержка >20с + Active инциденты

5. УПРАВЛЕНИЕ (/admin/page) — 3 вкладки
   - Сайты: CRUD (добавить/изменить/вкл/выкл/удалить), группы key/stdo/external, порог мин
   - Self Monitoring: async загрузка /api/self-monitoring (таблица + график + инциденты)
   - Описание: документация функционала (FUNCTIONAL.md через /api/functional)
   - Self-monitoring сайты защищены от изменения/удаления

6. TELEGRAM АЛЕРТЫ
   - Порог по умолчанию: 5 мин (настраивается в Управление → Порог мин для каждого сайта)
   - 🚨 DOWN: fail_count >= threshold + скриншот (3 сек после domcontentloaded)
   - ✅ UP: восстановление + скриншот + длительность (только если был DOWN алерт)
   - 🐢 Задержка: response_time > 20с
   - ⚡ Скорость восстановлена: response_time < 10с после задержки
   - 🔔 SSL отчет: SSL <= 20 дней (09:00 МСК)
     - Перед отправкой сертификаты проверяются заново, без использования старого счётчика из latest_status.
     - Исключены неактивные сайты, self-monitoring и сайты с отключённой проверкой SSL.
     - Если актуальный срок получить не удалось, сайт пропускается в ежедневном Telegram-отчёте; причина остаётся в логах `[SSL REPORT SKIP]`. Старое число дней не используется. Если подтверждённых предупреждений нет, сообщение не отправляется.
     - Ежедневные напоминания сохраняются, пока сертификат входит в порог предупреждения.
   - 🧪 Тест скриншот: по кнопке (rate limit 30 сек/сайт)
   - Retry 3x, exponential backoff, логирование каждого вызова

7. SELF-MONITORING (sib-monitor-ankori.amvera.io)
   - Изолирован: не в KPI "Доступно", не в общей таблице dashboard, не в группах
   - Проверка: любой HTTP-ответ = Online (200), только timeout = Offline (0)
   - Алерты: порог 10 мин, помечены [SELF-MONITORING] в Telegram
   - Cleanup при старте: удаляются старые logs/checks_agg/incidents для SM
   - Fallback Online: если нет в БД — показывает status=200
   - Вкладка только в Управлении (не на главном dashboard)

8. ИНЦИДЕНТЫ + RESOLVED
   - Content match для Ключевых сайтов: при status=200 проверяется наличие текста 'sibur/сибур/СИБУР'
   - Content mismatch: status=701, отображается как 'Content Mismatch', алерт '🚨 DOWN: site (Код: 701)'
   - Инцидент регистрируется только если недоступность >= порога (по умолчанию 5 мин)
   - start_time инцидента = время первого фейла (хранится в first_fail_time)
   - Короткие падения (< порога): в логи пишутся, в incidents — нет, алерта нет
   - resolved: FALSE при создании, TRUE при закрытии
   - UP-алерт отправляется только если был DOWN-алерт
   - Таблица t3: колонка "Статус" (🔴 Active / ✅ Resolved), длительность пересчитывается динамически
   - Active инциденты показываются в блоке "⚠️ Обратите внимание"
   - При старте: закрываются "висящие" unresolved инциденты для сайтов, которые сейчас Online

9. CONTENT MATCH
   - Проверяется для Ключевых сайтов при КАЖДОМ status=200 (включая восстановление)
   - Паттерн: (?i)(sibur|сибур|СИБУР) — case-insensitive
   - Чтение тела ответа: max 3 сек
   - Не найден или таймаут чтения → status=701 (Content Mismatch)
   - При восстановлении: UP алерт отправляется только после подтверждения content match (2 минуты подряд status=200)
   - Если контент пропадает после восстановления — сбрасывается up_alert_sent, fail_count продолжает расти
   - В таблице отображается красным: "Content Mismatch"
   - Алерт: "🚨 DOWN: site (Код: 701)"

10. ОПТИМИЗАЦИИ
    - Batch-вставка: накопление до 50 записей
    - Dashboard кэш: 30 сек, сборка <10 мс
    - Lazy charts: графики подгружаются async после first paint
    - string.Template для JS: устранён конфликт { } между Python f-string и JS
    - Playwright скриншоты: thread-safe, rate limit 30 сек, 3 сек после domcontentloaded
    - Скриншот с retry: 2 попытки с паузой 3 сек, таймаут 60 сек
    - Формат JPEG (.jpg), проверка размера (>1KB), логирование каждой попытки
    - Горизонтальная прокрутка таблиц (overflow-x: auto)
    - Столбец "Сайт" nowrap + min-width, столбец "Начало" 11ch

11. АУТЕНТИФИКАЦИЯ
    - Dashboard: Basic Auth + BCrypt + cookie session_auth (30 дней)
    - Admin: отдельный пароль + cookie admin_session (1 день)

=== ИСПРАВЛЕННЫЕ ОШИБКИ ===
1. JS SyntaxError: string.Template вместо f-string в JS
2. alert_threshold=None: защита на 3 уровнях (load_active_sites + _process_site_result + check_worker)
3. ssl_whois_worker не запускался: восстановлен в startup_event
4. Self-monitoring 401→Offline: любой HTTP=Online
5. Висящие unresolved инциденты: закрываются при старте
6. _backfill_incidents: исключает self-monitoring
7. Self-monitoring инициализация: last_status/fail_count/latency_map/first_fail_time
8. Алерт через 1 мин: last_status обновлялся при fail_count==1 (починено)
9. Длительность инцидентов: start_time = время первого фейла (не достижения порога)
10. Календарь пустой: исправлена HTML-структура (закрывающие div)
11. Self-monitoring алерты: добавлены с порогом 10 мин
12. Content match: добавлена проверка текста для Ключевых сайтов
13. Застывший срок SSL: минутный HTTP-воркер больше не перезаписывает SSL/WHOIS старым снимком из буфера. Утренний отчёт использует свежую проверку, ошибки фонового сохранения и формирования отчёта логируются.
14. Диагностика недоступности: причина сохраняется вместе с HTTP-результатом в latest_status.
    Миграция добавляет только nullable-колонку check_error и не удаляет существующие данные.
    История logs/incidents не расширяется: подробная причина доступна для последнего результата.
    Тело ответа и URL из исключений в диагностику не включаются.
    Правила статусов, Content Match и проверка TLS не ослаблены.
    HTTP-таймаут теперь настраивается отдельно для каждого сайта (см. ниже).
15. Журнал контейнера: PYTHONUNBUFFERED=1, причины повторяются в [CHECK SUMMARY ERROR].
    Метка версии доступна в заголовке панели, /health и [STARTUP].

=== ПРОВЕРКА РЕГРЕССИЙ ===
После установки requirements.txt: python -m unittest discover -s tests -v
Тесты не обращаются к рабочей БД, сайтам или Telegram.
Для интеграционных тестов задайте SIB_MONITOR_TEST_DSN отдельной тестовой PostgreSQL.
Они создают и удаляют только собственную временную схему; DATABASE_URL не используется.

=== ВРЕМЕННЫЙ СЕТЕВОЙ ДИАГНОСТИЧЕСКИЙ ПРОГОН ===
Версия 2026.10.30-netprobe.1 запускает один проход на каждый запуск процесса приложения.
По завершении нет повторов или расписания. Отключение: NETWORK_DIAGNOSTICS_ENABLED=0.
Строки имеют префикс [NET DIAG]; окончание прохода: stage=DONE.
Параллельно выполняются не более двух проб, общий лимит каждой — 30 секунд.
- Для sibur.ru, shop.sibur.ru, rusvinyl.ru, greencity-sibur.ru: openssl s_client
  получает только публичную цепочку сертификатов, без HTTP-запроса. Выводятся
  subject, issuer, сроки, SHA-256 отпечаток и ошибки проверки доверия.
  Полученные метаданные не считаются доверенными, сертификаты не устанавливаются.
- Для девяти сайтов с таймаутами: DNS, TCP, строгая TLS-проверка, HTTP-заголовки.
  Проверяется один HTTPS-запрос. Перенаправления отмечаются, но не выполняются;
  тело ответа не проверяется, Content Match не запускается. Успешный ответ пробы
  не означает прохождение полного рабочего сценария мониторинга.
- При таймауте процесса смотрите последний начатый этап без результата.
- Нет записи в БД, изменения статусов, доверенных CA, восьмисекундного рабочего
  таймаута и отправки Telegram. URL-параметры, cookies, авторизация и тела ответов
  в диагностические логи не включаются.

=== ИНДИВИДУАЛЬНЫЙ HTTP-ТАЙМАУТ ===
Управление → Сайты → Изменить → Таймаут, с → Сохранить.
Текущее значение показано в колонке «Таймаут HTTP, с». Поле есть и при добавлении.
Допустимо 1–60 секунд; не путать с порогом инцидента в минутах.
Настройка сохраняется в БД и читается в начале следующего цикла, без перезапуска.
Это общий лимит HTTP-запроса: подключение, TLS, перенаправления и чтение ответа.
Тестер Content Match в админке использует то же значение; отдельного ограничения
чтения тела в 10 секунд больше нет. Текст таймаута показывает выбранный лимит.
При больших значениях цикл может стать длиннее минуты. Пороги инцидентов продолжают
использовать существующий счётчик неуспешных циклов; их логика здесь не менялась.
SSL/WHOIS, self-monitoring, скриншоты и отдельный NET DIAG сохраняют свои лимиты.

Одноразовая миграция выставляет 30 секунд десяти существующим сайтам:
transportorder.sibur.ru, cp.tdms.sibur.ru/cp/, tst-stdo.tdms.sibur.ru/cp/,
bopp.sibur.ru, eshop.sibur.ru, srm.sibur.ru, resti.club, lsdts.sibur.ru,
tms.sibur.ru, sharefile.sibur.ru. Остальные получают исходные 8 секунд.
Метка app_meta.http_timeout_experiment_20261030_v1 предотвращает повторный сброс
ручных настроек при последующих запусках. SSL/CM, активность, пороги и история
не изменяются. Для отмены эксперимента установите нужным сайтам 8 секунд в админке.
