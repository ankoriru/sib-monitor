# Правила разработки и эксплуатации sib-monitor

Обязательны для каждого изменения. Документ обновляется при появлении новых требований
владельца продукта. Копия хранится в файлах проекта «Мониторинг сайтов» в Perplexity.

Последнее обновление: 2026-11-08 (2026.11.08-monitor.11).

## 1. Выкладка
1. Каждый push в `main` (github.com/ankoriru/sib-monitor) — только после явного
   согласования конкретного коммита: «Push в main» или «Через Pull Request».
   Согласие не переносится на следующий коммит.
2. Перед каждым релизом выполняется QA, после выкладки — QC (см. QA_QC.md):
   проверяются функциональные и нефункциональные требования, чтобы не сломать
   существующий функционал.
   - QA: `bash scripts/qa_pre_release.sh` — FAIL=0, иначе релиз не отправляется.
   - QC: `scripts/qc_post_release.py` против рабочего адреса и базовой линии; при
     FAIL по REL-1, NFR-AVAIL-1, NFR-WORKER-1 или REG-1 релиз откатывается.
3. В каждом релизе поднимается `APP_VERSION` (формат `ГГГГ.ММ.ДД-monitor.N`).

## 2. Документация после каждого релиза
1. Обновляется «📖 Описание функционала» в админке (FUNCTIONAL.md): строка «Версия»,
   HLD, схема развёртывания, C4 (контекст, контейнеры, компоненты) и детальное
   описание работы продукта.
2. В CHANGELOG.md добавляется запись `## <версия> — <дата выкладки МСК>` с разделами
   «Улучшения», «Исправлено», «Прочее» — понятным пользователю языком.
3. QA-4 проверяет оба пункта автоматически.

## 3. Ежедневная сводка изменений
1. Если за сутки были релизы, в 23:30 МСК в Telegram уходит краткая выжимка:
   улучшения, устранённые ошибки, прочие изменения работы продукта.
2. Если релизов не было — ничего не отправляется.
3. Сводка отправляется один раз за день (отметка в `app_meta`).

## 4. Правила проверок
1. HTTP 200 и HTTP 401 — сайт доступен.
2. Предупреждение о задержке — только при ответе строго дольше 25 секунд.
3. Сайты с самоподписанным сертификатом (и сертификатом корпоративного УЦ) проверяются
   и не считаются ошибкой при действующем сроке и верном имени; в строке сайта
   выделяется только пометка «🔓 самоподписанный сертификат».
4. Неполная цепочка сертификата достраивается по AIA, как в браузере.
5. Globalping (резервная внешняя проверка) работает только когда основной тест
   недоступен по сети (таймаут, DNS, отказ соединения). Ошибки HTTP, TLS и
   содержимого им не подменяются. Квота: не больше 230 тестов в час, не чаще раза
   в 10 минут на сайт.
6. Внешний маршрут проверки не выделяется в обычном интерфейсе и уведомлениях.
7. tst-stdo исключён из мониторинга. Самопроверка использует актуальный домен
   https://sib-monitor-ankori.msk1.amvera.tech/ с сохранением истории.

## 5. Безопасность
1. Секреты не выводятся в журнал и не коммитятся.
2. Открытый вопрос SEC-1: статичные значения cookie сессии нужно заменить на случайные
   подписанные сессии.
