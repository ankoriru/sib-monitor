# Резервная проверка Globalping

Версия: 2026.11.05-monitor.4. Рабочая публикация: существующее приложение
sib-monitor в Amvera Moscow-1, домен https://sib-monitor-ankori.msk1.amvera.tech/.

## Область применения

Резерв применяется ко всем активным публичным DNS-адресам из реестра монитора,
только после сетевой ошибки прямого запроса. Локальные/зарезервированные имена,
IP-литералы, нестандартные порты, credentials и query strings исключены.
Успешный прямой результат,
HTTP-ошибка, ошибка TLS или Content Match не подменяются внешней проверкой.
Прямые запросы по-прежнему выполняются каждый цикл.

Globalping вызывается без ключа. Один запрос запускает два HTTPS GET из России;
конкретные сети назначает сервис. Результаты сохраняют фактические сети, а не
предполагают независимость двух узлов. Резервные измерения обновляются раз в
10 минут. Внутрипроцессный скользящий лимит: 230 тестов в час, каждый запрос
резервирует два теста, включая повторные проверки страниц перенаправления.
Общий внешний лимит IP может быть занят другими приложениями.
При массовом сбое всех 52 сайтов два узла каждые 10 минут потребовали бы
624 теста/час, больше бесплатного лимита без регистрации. Поэтому 10 минут
являются минимальным интервалом, а не гарантией при исчерпании квоты:
в этом случае результат явно «Не подтверждено», без повторного использования
просроченного успеха. Существующий успешный прямой мониторинг квоту не расходует.

HTTP 429 включает паузу по Retry-After (60–3600 секунд, по умолчанию 3600).
Возраст успешного результата никогда не превышает 600 секунд; после истечения
и неудачи обновления старый успех не используется. Кэш отмечен в диагностике.
Общий дедлайн одной резервной проверки: 50 секунд; параллелизм: три сайта.

## Интерпретация

- HTTP 200: успех только с учётом настроек TLS и Content Match сайта.
- HTTP 401: доступность подтверждена; проверка содержимого не нужна.
- Редирект не означает успех сам по себе. Выполняется до трёх измерений,
  допускаются только HTTPS на том же хосте, порт 443, без credentials/query/fragment.
- HTTP 403 остаётся ошибкой доступа, а не успешной авторизацией.
- Неподтверждённый TLS при включённом ssl_verify: внутренний код 703.
- Content Match без совпадения: 701; отсутствующее/усечённое содержимое без
  совпадения не позволяет вынести отрицательный вывод: 702.
- Нет ответа, ошибка API, лимит, небезопасный/непроверенный редирект: 702,
  «Не подтверждено». Это не DOWN и не UP.

Одного соответствующего политике успешного внешнего результата достаточно,
чтобы показать обычный зелёный «Online». По решению пользователя источник
измерения является внутренним механизмом: в пользовательском интерфейсе
и уведомлениях нет отдельных меток, предупреждений, счётчиков, времени кэша
или ссылок на узлы Globalping. HTTP/TLS/Content Match ошибки не скрываются,
но показываются обычным способом. Это не утверждение о доступности со всех сетей.

## Уточнённый путь tst-stdo

Для исторического ключа `tst-stdo.tdms.sibur.ru/cp/` обе проверки выполняют
запрос к `https://tst-stdo.tdms.sibur.ru/cp/component/main`.
Ссылка и подпись в списке, запросы скриншотов и уведомления используют
уточнённый путь. Ключи таблиц, настройки, категории, история и инциденты
не переименовываются, не удаляются и не создаются заново. Соответствие
содержится в `check_targets.py`; кэш зависит также от фактического URL.

## Данные, метрики и инциденты

Аддитивная миграция: nullable JSONB `latest_status.check_details`.
Сохраняются прямой результат, внешний результат, время, идентификаторы измерений,
сеть, HTTP/TLS и результат Content Match. Заголовки, cookies и тела не сохраняются
в БД/логах приложения. При прямом восстановлении внешние сведения очищаются.

Globalping является внешним публичным сервисом: результаты измерений могут
содержать ответ публичной страницы. Приложение не отправляет туда пользовательские
cookies, логины, пароли, токены или произвольные URL. Не добавлять закрытые
адреса в реестр публичного мониторинга без отдельного согласования.

Статус 702 записывается только в latest_status, не включается в logs и checks_agg:
нет подтверждённого измерения, значит нет ни uptime, ни downtime. Исторические
метрики отражают только определённые результаты и не доказывают доступность
во время пробелов. Старые метрики не переписываются. Кэшированные определённые
результаты отражаются в минутных агрегатах, с временем измерения в диагностике.

Неопределённость не открывает и не закрывает инциденты, сбрасывает счётчик
последовательных отказов. Старый активный инцидент остаётся до успешной проверки.
Свежий внешний успех может закрыть старый инцидент, но не означает
восстановления маршрута Amvera. Пользовательские уведомления не раскрывают
внутренний механизм проверки, согласно уточнению пользователя.
Безусловное закрытие инцидентов sharefile при запуске удалено.

## Отключение и откат

Установить `GLOBALPING_ENABLED=false` и штатно перезапустить приложение:
останутся прямые проверки, внешние сведения очистятся следующим циклом.
Ключ Globalping, платный аккаунт и новый сервер не требуются.

Откат к предыдущему коммиту совместим с добавленным nullable столбцом.
Откат старого кода не восстанавливает прежние значения статуса автоматически:
после первого прямого цикла они обновятся. История до и после публикации сохранена.
